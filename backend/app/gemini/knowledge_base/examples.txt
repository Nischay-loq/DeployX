================================

- Deploy files to that server
- Run commands remotely
- Monitor CPU, RAM, and disk usage
- Manage files without SSH

To add an agent:
1. Click **Agents** in the sidebar
2. Click **Add Agent** button
3. Download and install on your server

The agent runs in the background and keeps your server connected to DeployX."

CATEGORY: FILE UPLOADS
================================

Q: "How do I upload files to my server?"
A: "To upload files to your server:

1. Click **Files** in the left sidebar (folder icon 📁)
2. At the top, select your server from the **device dropdown**
3. Navigate to where you want the files to go:
   - Click folders in the tree on the left, OR
   - Use the breadcrumb path at the top
4. Click the **Upload** button (blue, top-right corner)
5. Select files from your computer
6. Click **Open** to start uploading

**Important**:
- Max file size: 100MB per file
- Make sure the agent is online (green status)
- Ensure you have write permissions for that folder

Files will appear in the current directory once uploaded!"

---

Q: "Can I upload multiple files at once?"
A: "Yes! You can upload multiple files in one go.

When you click the **Upload** button on the Files page:
1. Hold **Ctrl** (Windows/Linux) or **Cmd** (Mac)
2. Click each file you want to upload
3. Click **Open**

All selected files will upload together. You'll see individual progress bars for each file.

**Note**: Each file must be under 100MB, but you can upload as many as you need!"

---

Q: "File upload failed, what do I do?"
A: "Let's troubleshoot your upload issue:

**Common Causes & Solutions**:

**File Too Large**:
- Max size is 100MB per file
- Solution: Split large files or use compression

**Agent Offline**:
- Check if your device shows green **Online** status
- Solution: Restart the agent service on your server

**No Write Permission**:
- The agent needs permission to write to that folder
- Solution: Try uploading to a different folder, or change folder permissions

**Network Issue**:
- Poor connection can interrupt uploads
- Solution: Try uploading smaller files first to test

**Disk Full**:
- Target server might be out of space
- Solution: Check disk usage on your device

Which error message are you seeing?"

---

Q: "Where did my uploaded files go?"
A: "Your uploaded files should be in the folder you were viewing when you clicked Upload.

To find them:

1. Go to **Files** page
2. Select the same device from the dropdown
3. Navigate to the destination folder (use breadcrumbs at top or folder tree on left)
4. Your files should be there!

**If you can't find them**:
- Click the **Refresh** button (circular arrows icon)
- Check that you're looking at the correct device
- Verify the upload actually completed (look for success notification)

**Tip**: The file browser shows the exact path at the top (like `/home/user/documents`). Remember this path to find your files easily!"

Q: "How do I deploy my application?"

- Click **Next**

**Step 5 - Deploy**:
- Choose "Deploy Now"

Need help with any specific step?"

Q: "My deployment failed, how do I fix it?"
A: "Let's fix your deployment! First, let's see what went wrong:

1. Go to **Deployments** page
2. Find your failed deployment (red **Failed** status)
3. Click on it to see details
4. Look at the error message

**Common Issues**:

**\"Permission denied\"**:
- The agent can't write to that folder
- **Fix**: Check folder permissions, or use a folder the agent can access

**\"No space left on device\"**:
- Server is out of disk space
- **Fix**: Free up space on the server, or deploy to a different location

**\"Connection timeout\" or \"Agent offline\"**:
- Lost connection to server
- **Fix**: Check the agent is online (green status), restart if needed

**\"File not found\" or \"No such directory\"**:
- Destination path doesn't exist
- **Fix**: Create the folder first, or use an existing path

Once you fix the issue:
- Click the **Retry** button on the deployment

What error message are you seeing? I can give you more specific help!"

CATEGORY: COMMANDS

Q: "How do I run a command on my server?"
A: "To execute a command on your server:

1. Click **Commands** in the sidebar (terminal icon ⌨️)
2. At the top, select your target:
   - Choose "Single Device", "Device Group", or "Multiple Devices"
   - Pick which server(s) from the dropdown
3. Type your command in the text box
   - Example: `ls -la` or `systemctl status nginx`
4. (Optional) Check **Run as sudo** if you need admin rights
5. Click the **Execute** button (green)

You'll see the command running, then get the output!

**Examples**:
- Check disk space: `df -h`
- See running processes: `ps aux`
- Restart a service: `systemctl restart nginx`
- View file contents: `cat /path/to/file.txt`

What command do you want to run?"

---

Q: "Can I run commands on multiple servers at once?"
A: "Absolutely! You can run the same command across multiple servers:

**Method 1: Use a Device Group**
1. First, create a group with your servers:
   - Go to **Device Groups** page
   - Click **Create Group**
   - Select the servers
   - Click **Create**
2. Then go to **Commands** page
3. Select "Device Group" from the target dropdown
4. Choose your group
5. Enter your command
6. Click **Execute**

The command runs on all servers in the group!

**Method 2: Select Multiple Devices**
1. Go to **Commands** page
2. Select "Multiple Devices"
3. Check the boxes for each server you want
4. Enter your command
5. Click **Execute**

You'll see results for each server separately.

**Perfect For**:
- Restarting services across all web servers
- Updating packages on multiple machines
- Checking disk space on all servers

Want me to help you create a device group?"

---

Q: "Command is taking too long and failed with timeout"
A: "Sounds like your command needs more time to complete!

**Solution**: Increase the timeout setting:

1. Go to **Commands** page
2. Enter your command
3. Look for the **Timeout** field (below the command box)
4. Change it from 30 to a higher number (e.g., 60, 120, or 300)
   - This is in seconds
5. Click **Execute**

**Timeout Guidelines**:
- Simple commands (ls, cat): 30 seconds (default)
- Package updates (apt update): 60-120 seconds
- Installs (apt install): 120-300 seconds
- Large downloads/builds: 600+ seconds

**Alternative**: Use Interactive Terminal
- Click **Open Terminal** button
- Run long commands interactively
- No timeout limits

What command are you trying to run? I can suggest a good timeout value!"

Q: "My agent shows offline, how do I fix it?"

- Can you ping it?

**Step 2: Restart the Agent**

  * **Windows**: Open Services, find DeployX Agent, click Restart

**Step 3: Check Agent Logs**
- Look for errors:
  * **Linux**: `tail -f /var/log/deployx/agent.log`
  * **Windows**: `C:\\ProgramData\\DeployX\\logs\\agent.log`

**Step 4: Check Firewall**
- Make sure outbound connections are allowed
- The agent needs to reach your DeployX server

**Step 5: Reinstall (Last Resort)**
- Download fresh installer from **Add Agent** button
- Uninstall old agent
- Install new agent
- It will reconnect automatically

**Still Offline?**
- Check the logs and tell me what error you see
- I can help you troubleshoot further!

Which step are you on?"

Q: "What's the difference between agents and devices?"
A: "Good question! Here's the difference:

**Agent** = The software program
- A program you install on your server
- Runs in the background
- Connects your server to DeployX
- One agent per machine

**Device** = The actual server/machine
- The physical or virtual machine
- Has an agent installed on it
- Shows up in your devices list
- Has CPU, RAM, disk metrics

**Analogy**:
- Device = Your phone
- Agent = The app on your phone

**In DeployX**:
- **Agents** page: See connected agents, their status, metrics
- **Devices** page: See all registered devices with health info

Both pages show similar info, but:
- **Agents**: Focus on connection and agent status
- **Devices**: Focus on hardware health and grouping

You'll mostly use the **Agents** page to manage connections!"

Q: "Error: Permission denied"
A: "This \"Permission denied\" error means access rights are missing. Let's fix it:

**Where Are You Seeing This?**

**If During File Upload**:
1. The agent needs write permission to that folder
2. **Solution**: Upload to a different folder like `/tmp` or `/home/user`
3. Or SSH to server and run:
   ```
   sudo chmod 755 /path/to/folder
   sudo chown agent-user /path/to/folder
   ```

**If During Deployment**:
1. Check **Backup Before Deploy** isn't checked to use a read-only location
2. Change destination path to writable location
3. Or add pre-deployment command:
   ```
   sudo mkdir -p /destination/path
   sudo chmod 755 /destination/path
   ```

**If Running Commands**:
1. Command needs admin rights
2. **Solution**: Check **Run as sudo** box before executing
3. Or modify your command to include sudo

**If In File Browser**:
1. You're trying to access a protected folder
2. Navigate to folders your user can access

Q: "Can I run deployments in parallel?"

**How It Works**:
- When you deploy to multiple devices/groups
- Each device gets its deployment simultaneously
- They don't wait for each other

**Example**:

- All 10 start at the same time

**Benefits**:

- Scales well with many devices

**To See Progress**:
- Go to deployment details
- Click **Targets** tab
- See status for each device in real-time

**If One Fails**:
- Others continue running
- Failed device shown in red
- You can retry just the failed one

**Control Speed**:
- No setting to limit parallel deployments
- If you want sequential, create separate deployments
- Or deploy to groups one at a time

**Performance**:
- Your DeployX server handles the coordination
- Each agent works independently
- Typically fast unless server is overloaded

This is one of DeployX's biggest advantages - fast, parallel deployments!"

Q: "How do I deploy to production safely?"
A: "Great question! Here's how to deploy safely to production:

**Pre-Deployment Checklist**:

**1. Test First**
- Deploy to dev/staging environment
- Verify everything works
- Run tests

**2. Create Production Group**
- Go to **Device Groups**
- Create \"Production Servers\" group
- Add only production machines

**3. Enable Backups**
- ✅ Always check **Backup Before Deploy**
- This is your rollback insurance

**4. Schedule During Low Traffic**
- Use **Schedules** page
- Deploy at 2-4 AM when users are asleep
- Or during maintenance windows

**5. Add Health Checks**
- Post-deployment commands:
   ```
   systemctl status myapp
   curl -f http://localhost/health || exit 1
   ```

**Safe Deployment Strategy**:

**Option A: Staged Rollout**
1. Deploy to 1 production server first
2. Monitor for 10-15 minutes
3. If good, deploy to rest

**Option B: Blue-Green**
1. Keep old version running (Blue)
2. Deploy new version to standby servers (Green)
3. Test Green
4. Switch traffic from Blue to Green
5. Keep Blue as backup

**During Deployment**:
- Watch the progress in real-time
- Check logs immediately
- Monitor server metrics

**After Deployment**:
1. Test critical features
2. Check error logs
3. Monitor user reports
4. Keep backup ready for 24 hours

**If Something Goes Wrong**:
1. Go to **Backups** page immediately
2. Click **Restore**
3. You're back to working version in minutes

**Pro Tips**:
- Deploy on Tuesdays/Wednesdays (not Fridays!)
- Have someone on standby to monitor
- Document what you deployed
- Keep deployment notes

Want me to walk you through your first production deployment?"
