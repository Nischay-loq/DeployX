1. PLATFORM OVERVIEW
================================

DeployX is a deployment automation platform that helps users:
- Manage multiple servers/devices from one dashboard
- Deploy applications and files to remote servers
- Execute commands across multiple machines
- Schedule automated tasks
- Monitor device health and performance
- Group devices for bulk operations
- Backup and rollback deployments

Key Features:
✓ Real-time device monitoring
✓ Multi-device command execution
✓ File transfer and management
✓ Automated deployment scheduling
✓ Device grouping for organized management
✓ Comprehensive logging and history
✓ Backup and restore capabilities

  * Shows full system specs

- **Execute Command** button

  * See command output in real-time

- **View Files** button
  * Opens file browser for this agent
  * Browse remote file system
  * Upload/download files

If no agents connected:
- Shows: "No agents connected" message
- Shows: "Add Agent" button
- Instructions: How to install agent on devices

1. Click **Add Agent** button (blue, top-right)
2. Downloads agent installer
3. Choose platform:
   - Windows installer (.exe)
   - Linux installer (.sh)
   - macOS installer (.dmg)
4. Run installer on target device

7. DEPLOYMENTS PAGE
================================

Location: Click **Deployments** in sidebar
Purpose: Create and manage software deployments

## Page Layout:

### Top Actions Bar
- **Create Deployment** button (green, top-right)
  * Icon: Plus + rocket
  * Opens deployment creation form

### Deployments List/Table
Shows all deployments with columns:

**Deployment Name**
- Main identifier
- Click to view details

**Target** (Where deployed)
- Device name, or
- Group name, or
- Multiple targets count

**Status**
- 🟢 "Successful" (green)
- 🔴 "Failed" (red)
- 🟡 "Pending" (yellow)
- 🔵 "Running" (blue, animated)

**Progress Bar** (for running deployments)
- Shows completion percentage
- Animated while running

**Created Date**
- When deployment was created
- Format: "Dec 27, 2025"

**Actions** (buttons)
- **View Details**: See full deployment info
- **Retry**: Run deployment again (if failed)
- **Rollback**: Undo deployment (if backed up)
- **Delete**: Remove from history

### Creating a Deployment
1. Click **Create Deployment** button
2. Form modal opens with fields:

**Step 1: Deployment Information**
- **Deployment Name** (required)
  * Text field
  * Example: "Production App v2.0"
  
- **Description** (optional)
  * Text area
  * What this deployment does

**Step 2: Select Targets**
- **Target Type** dropdown:
  * "Single Device"
  * "Device Group"
  * "Multiple Devices"
  
- **Device/Group Selector**:
  * If "Single Device": Dropdown of devices
  * If "Device Group": Dropdown of groups
  * If "Multiple": Checkboxes for devices

**Step 3: Select Files/Application**
- **Upload Files** button
  * Opens file picker
  * Multiple files allowed
  * Max 100MB per file
  * Shows selected files list
  
- OR **Select from Repository**
  * Choose from previously uploaded files

**Step 4: Deployment Settings**
- **Destination Path** (required)
  * Text field
  * Where files go on target
  * Example: "/var/www/html"
  
- **Pre-deployment Commands** (optional)
  * Commands to run before deployment
  * Example: "systemctl stop nginx"
  
- **Post-deployment Commands** (optional)
  * Commands to run after deployment
  * Example: "systemctl start nginx"
  
- **Backup Before Deploy** (checkbox)
  * Creates backup for rollback
  * Recommended: Checked

**Step 5: Schedule (Optional)**
- **Deploy Now** (default)
  * Runs immediately
  
- OR **Schedule for Later**
  * Date picker
  * Time picker
  * Timezone selector

3. Click **Deploy** button (green)
4. Deployment starts immediately or scheduled
5. Progress shown in real-time

### Viewing Deployment Details
Click any deployment to see:
- Full configuration
- Target devices list
- File list
- Command execution logs
- Success/failure status per device
- Error messages (if failed)
- Deployment timeline
- Actions: Retry, Rollback, Delete

- **New Folder** button
  * Icon: Folder plus
  * Create new directory
  
- **Refresh** button
  * Icon: Circular arrows

### File Browser (Main Area)
Split into two panes:

**Left Pane: Directory Tree**
- Hierarchical folder structure
- Click folder to expand/collapse
- Shows folder icon
- Click to navigate

**Right Pane: File List**
Table showing current directory contents:

Columns:

1. Select target device from dropdown

3. Click **Upload** button (blue, top-right)

6. Progress bar shows upload status
7. Files appear in current directory
8. Success notification appears

- Ensure device is online
- Check write permissions
- Verify sufficient disk space

### Downloading Files
1. Navigate to file location
2. Click **Download** button on file row
3. File downloads to your computer
4. Browser's download location

### Creating Folders
1. Click **New Folder** button
2. Modal opens:
   - **Folder Name** field
3. Enter folder name
4. Click **Create** button
5. Folder appears in list

### Deleting Files/Folders
1. Select file(s) or folder(s):
   - Click checkbox next to items, OR
   - Click **Delete** button on row
2. Confirmation dialog:
   - "Are you sure?"
   - **Cancel** (gray)
   - **Delete** (red)
3. Item removed from device

### Common Use Cases:
- Upload application files to servers
- Download logs for analysis
- Clean up old files
- Organize deployment artifacts
- Transfer configuration files

9. COMMANDS PAGE
================================

Location: Click **Commands** in sidebar
Purpose: Execute commands on remote devices

## Page Layout:

### Command Execution Panel (Top)

**Target Selection**
- **Select Target** dropdown:
  * "Single Device"
  * "Device Group"
  * "Multiple Devices"
- Second dropdown: Choose specific target(s)

**Command Input**
- **Command** text field (required)
  * Placeholder: "Enter command to execute..."
  * Example: "ls -la", "systemctl status nginx"
  * Supports shell commands

**Execution Options**
- **Run as sudo** checkbox
  * Execute with elevated privileges
  
- **Timeout** field
  * Seconds before command times out
  * Default: 30 seconds

**Action Button**
- **Execute** button (green)
  * Icon: Play icon
  * Runs command on selected targets

### Command History (Below)
Table showing previous commands:

Columns:
- **Command**: Command text
- **Target**: Device/group name
- **Status**: 
  * ✅ "Success" (green)
  * ❌ "Failed" (red)
  * ⏳ "Running" (blue, animated)
- **Exit Code**: Command exit code (0 = success)
- **Executed**: Date and time
- **Actions**: 
  * **View Output** button
  * **Rerun** button
  * **Delete** button

### Interactive Terminal (Optional)
For real-time command execution:

1. Click **Open Terminal** button
2. Terminal window opens
3. Select device
4. Type commands interactively
5. See output in real-time
6. Terminal features:
   - Command history (up/down arrows)
   - Tab completion
   - Copy/paste support
   - Clear screen option
   - Close terminal button

### Executing Commands
1. Select target (device/group)
2. Type command in input field
3. (Optional) Check "Run as sudo"
4. (Optional) Set timeout
5. Click **Execute** button
6. Command runs on target(s)
7. Output appears in popup or history
8. Status indicator shows success/failure

### Viewing Command Output
1. Find command in history
2. Click **View Output** button
3. Modal opens showing:
   - Full command
   - Target device(s)
   - Standard output (stdout)
   - Error output (stderr)
   - Exit code
   - Execution time
   - Timestamp

### Common Commands:
- System info: `uname -a`, `lsb_release -a`
- Process management: `systemctl status nginx`, `pm2 list`
- File operations: `ls -la`, `du -sh`, `df -h`
- Network: `ping google.com`, `netstat -tulpn`
- Updates: `apt update`, `yum update`

10. BACKUPS PAGE
================================

Location: Click **Backups** in sidebar
Purpose: Manage deployment backups and perform rollbacks

## Page Layout:

### Backups List
Table showing all backups:

Columns:
- **Backup Name**: Identifier
- **Deployment**: Associated deployment name
- **Device**: Target device
- **Created**: Backup date/time
- **Size**: Backup size (MB/GB)
- **Status**: 
  * "Valid" (green)
  * "Corrupted" (red)
- **Actions**:
  * **Restore** button (blue)
  * **Download** button
  * **Delete** button (red)

### Backup Details
Click any backup to view:
- Full backup information
- Files included
- Deployment configuration
- Backup metadata
- Restore preview

### Restoring a Backup (Rollback)
1. Find backup in list
2. Click **Restore** button
3. Confirmation dialog:
   - "This will restore files to previous state"
   - Shows: Files to be restored
   - Shows: Target device
   - **Cancel** (gray)
   - **Restore** (blue)
4. Restoration process starts
5. Progress bar shown
6. Success/failure notification
7. Device reverted to backed-up state

### Automatic Backups
Backups are created automatically when:
- "Backup Before Deploy" is checked during deployment
- Before overwriting existing files
- Before destructive operations

### Manual Backup
To create manual backup:
1. Go to Deployments page
2. Find deployment to backup
3. Click **Actions** menu
4. Select **Create Backup**
5. Backup created and listed

### Deleting Backups
1. Click **Delete** button (red trash icon)
2. Confirmation required
3. Backup permanently removed
4. Cannot be restored after deletion

### Backup Best Practices:
- Always backup before major deployments
- Regularly clean old backups
- Download critical backups locally
- Test restores periodically
- Keep at least one backup per deployment

11. SCHEDULES PAGE
================================

Location: Click **Schedules** in sidebar
Purpose: Create and manage automated deployment schedules

## Page Layout:

### Top Actions
- **Create Schedule** button (green, top-right)
  * Opens schedule creation form

### Schedules List
Table showing all schedules:

Columns:
- **Schedule Name**: Identifier
- **Deployment**: Associated deployment
- **Frequency**: How often runs
  * "One-time"
  * "Daily"
  * "Weekly"
  * "Monthly"
  * "Custom (Cron)"
- **Next Run**: When next execution
- **Status**: 
  * "Active" (green)
  * "Paused" (yellow)
  * "Expired" (gray)
- **Actions**:
  * **Edit** button
  * **Pause/Resume** toggle
  * **Delete** button

### Creating a Schedule
1. Click **Create Schedule** button
2. Form opens with fields:

**Schedule Information**
- **Schedule Name** (required)
  * Text field
  
- **Description** (optional)
  * What this schedule does

**Select Deployment**
- **Deployment** dropdown (required)
  * Choose existing deployment
  * Or create new deployment

**Schedule Type**
- **One-time**: Runs once
  * Date picker
  * Time picker
  
- **Recurring**: Runs repeatedly
  * **Frequency** dropdown:
    - Daily
    - Weekly
    - Monthly
    - Custom (Cron expression)
  
  * If Daily:
    - Time picker
  
  * If Weekly:
    - Day selector (checkboxes)
    - Time picker
  
  * If Monthly:
    - Day of month (1-31)
    - Time picker
  
  * If Custom:
    - Cron expression field
    - Example: "0 2 * * *" (2 AM daily)

**Additional Options**
- **Timezone** dropdown
  * Select appropriate timezone
  
- **Retry on Failure** checkbox
  * Automatically retry if deployment fails
  
- **Max Retries** field (if retry enabled)
  * Number of retry attempts

3. Click **Create Schedule** button
4. Schedule becomes active

### Editing a Schedule
1. Click **Edit** button on schedule row
2. Modify any fields
3. Click **Save Changes**
4. Next run time recalculates

### Pausing/Resuming Schedules
- Click **Pause** button to temporarily stop
- Schedule kept but not executed
- Click **Resume** to reactivate
- Next run time recalculates from now

### Deleting Schedules
1. Click **Delete** button
2. Confirmation required
3. Schedule removed
4. Past executions remain in history

### Schedule Monitoring
- View upcoming schedules
- See execution history
- Check success/failure rates
- Receive notifications on failures

15. TROUBLESHOOTING
================================

### PROBLEM: Agent Shows Offline
**Symptoms**: Agent has red "Offline" status

**Solutions**:
1. **Check device is powered on and connected to internet**
2. **Restart agent service**:
   - Linux: `sudo systemctl restart deployx-agent`
   - Windows: Services → DeployX Agent → Restart
3. **Check agent logs**:
   - Location: `/var/log/deployx/agent.log` (Linux)
   - Location: `C:\ProgramData\DeployX\logs` (Windows)
4. **Verify firewall allows connections**:
   - Port: Usually 8000 or configured port
   - Allow outbound connections to DeployX server
5. **Reinstall agent if corrupted**

---

### PROBLEM: Deployment Failed
**Symptoms**: Deployment shows red "Failed" status

**Solutions**:
1. **Click deployment to view error message**
2. **Common errors**:
   
   **"Permission denied"**
   - Solution: Check file/folder permissions
   - Solution: Ensure agent has write access
   - Solution: Try with sudo in pre-deployment commands
   
   **"No space left on device"**
   - Solution: Check disk space on target device
   - Solution: Clean up old files
   - Solution: Deploy to different location
   
   **"Connection timeout"**
   - Solution: Check network connectivity
   - Solution: Increase timeout in deployment settings
   - Solution: Verify agent is online
   
   **"File not found"**
   - Solution: Check destination path exists
   - Solution: Create directory in pre-deployment commands
   - Solution: Verify file paths are correct

3. **Fix the issue and click Retry button**
4. **Check logs page for detailed error information**

---

### PROBLEM: File Upload Failing
**Symptoms**: Upload button doesn't work or upload fails midway

**Solutions**:
1. **Check file size**: Max 100MB per file
   - Solution: Split large files
   - Solution: Use compression
2. **Verify agent is online**
   - Green status indicator
3. **Check write permissions**:
   - Agent needs write access to destination folder
4. **Ensure sufficient disk space**:
   - Check device disk usage
5. **Try smaller files first**: Test upload with small file
6. **Check network stability**: Poor connection can interrupt uploads

---

### PROBLEM: Command Not Executing
**Symptoms**: Command shows "Failed" or no output

**Solutions**:
1. **Check command syntax**:
   - Test locally first
   - Verify command exists on target OS
2. **Check permissions**:
   - Try with "Run as sudo" checkbox
   - Verify user has permissions
3. **Check timeout setting**:
   - Increase timeout for long-running commands
4. **Verify agent is online**
5. **Check command output**:
   - Click "View Output" button
   - Read stderr for error messages
6. **Try interactive terminal**:
   - Click "Open Terminal"
   - Test commands manually

---

### PROBLEM: Schedule Not Running
**Symptoms**: Scheduled deployment doesn't execute

**Solutions**:
1. **Check schedule status**: Must be "Active" (green)
   - If "Paused", click Resume
2. **Verify next run time**:
   - Is it in the future?
   - Check timezone is correct
3. **Check associated deployment**:
   - Deployment must still exist
   - Deployment must be valid
4. **Review logs**:
   - Go to Logs page
   - Filter by "Schedules" category
   - Look for error messages
5. **Check agent availability**:
   - Target agents must be online at scheduled time
6. **Edit and save schedule**:
   - Sometimes recreating the schedule helps

---

### PROBLEM: Cannot See Devices
**Symptoms**: Devices page is empty or missing devices

**Solutions**:
1. **Ensure agents are installed and online**:
   - Go to Agents page
   - Check green "Online" status
2. **Refresh the page**: Click Refresh button or F5
3. **Check filters**:
   - Status filter: Set to "All Statuses"
   - Group filter: Set to "All Groups"
   - Search box: Clear any search terms
4. **Check authentication**:
   - Ensure you're logged in

5. **Check browser console**:
   - F12 → Console tab
   - Look for error messages

### PROBLEM: Backup Not Created
**Symptoms**: Cannot rollback, no backup available

**Solutions**:
1. **Ensure "Backup Before Deploy" was checked**:
   - This option must be enabled during deployment
   - It's not automatic otherwise
2. **Check disk space on server**:
   - Backups require storage space
   - Clean old backups if needed
3. **Verify backup location permissions**:
   - Agent needs write access to backup directory
4. **Manual backup**:
   - Go to Deployments page
   - Click deployment Actions → Create Backup
5. **For future**: Always check backup option in deployments

### COMMON ERROR MESSAGES

**"Authentication failed"**
- **Meaning**: Login credentials invalid
- **Solution**: Check username and password, reset if needed

**"Connection refused"**
- **Meaning**: Cannot reach target device
- **Solution**: Check network, firewall, agent status

**"Permission denied"**
- **Meaning**: Insufficient access rights
- **Solution**: Use sudo, check file/folder permissions

**"No such file or directory"**
- **Meaning**: Path doesn't exist
- **Solution**: Create directory first, check path spelling

**"Port already in use"**
- **Meaning**: Another app using the same port
- **Solution**: Stop other app, use different port

**"Timeout"**
- **Meaning**: Operation took too long
- **Solution**: Increase timeout setting, check network

**"Internal server error"**
- **Meaning**: Backend issue
- **Solution**: Check logs, contact support, try again

**"Agent offline"**
- **Meaning**: Target device not connected
- **Solution**: Start agent, check device connection

**"Insufficient disk space"**
- **Meaning**: Not enough storage
- **Solution**: Free up space, use different location

**"Invalid deployment configuration"**
- **Meaning**: Deployment settings incorrect
- **Solution**: Review deployment form, check required fields
